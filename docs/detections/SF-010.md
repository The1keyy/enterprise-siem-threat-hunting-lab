# SF-010 — Inbound RDP logon

## Objective

Alert when Security 4624 is a RemoteInteractive logon (type 10). A second rule raises the level when the account is the lab admin account, or when the computer is DC01. The technique is `T1021.001`.

## ATT&CK

`T1021.001` Remote Desktop Protocol. Lateral Movement.

## Telemetry

Audit Logon, Success, on WS01 (`10.10.10.20`) and DC01 (`10.10.10.10`). That policy writes 4624.

Chain: 60000 → 60001 → 60103 → 60106. File `0580-win-security_rules.xml`. Stock 92653 is `if_sid` 92651, logon type pattern `10` with no anchors, level 3, and also tags `T1078.002`. These rules add `^4624$` and `^10$`.

`win.eventdata.logonType`, `targetUserName`, and `ipAddress` are field checks in this ruleset. `win.system.computer` is the computer key in the 4624 sample comment above 60106. It is not a `<field>` check elsewhere.

## Logic

One type-10 logon is enough. This is not a frequency rule.

Rule 100500, level 10, is the baseline. Level 10 is medium (ADR 0004) and is above 92653, so a normal RDP logon is labeled SF-010. Loopback RDP is stock 92656, level 15. That rule stays the alert for a loopback source. This file does not outrank it.

Rule 100501, level 12, matches `targetUserName` `^sf-test-admin$` only. That is the documented lab admin account. It is not a search for the word admin. Real group membership is not known to this rule.

Rule 100502, level 12, matches computer `DC01` or `DC01.sentinelforge.lab`. RDP to the domain controller is high, not critical. Critical stays with SF-008, which is a Domain Admins or Enterprise Admins membership change. Level 12 is high and is the library severity because 100501 and 100502 are the elevated behavior.

Exclusions are anchored paths, addresses, and account forms. A string inside a message is not an exclusion. The account check is an exact name, which the attacker does not choose on someone else's 4624. The source address and the computer name are not the script text.

## Exclusions

- `targetUserName` ending in `$` (machine account), on 100500. The elevated rules chain from 100500, so they inherit the miss.
- `ipAddress` exactly `10.10.10.1`, the lab host adapter. WS01 `10.10.10.20` is the planned simulation source and is not excluded.
- The Wazuh agent path is not applied here. `processName` appears only in the 4624 sample comment, not as a `<field>` check. Negating it could drop a 4624 that omits the field. The agent path is on SF-012.

## Validation procedure

Mac: `make logtest ID=SF-010` prints LIMITED.

Lab simulation not run. **REQUIRES WINDOWS VALIDATION.**

1. Snapshot WS01 and DC01 first.
2. On WS01, run `scripts/powershell/simulations/SF-010-Rdp.ps1` and follow the `mstsc` steps. Use `sf-test-admin` for the elevated account case, and DC01 for the computer case. `mstsc` cannot bind to `10.10.10.200`. Expect `ipAddress` `10.10.10.20`.
3. Log off the session. Delete leftover `sf-test-*` accounts. Restore the snapshot if the host changed.

## Expected result

Rule 100500, level 10, for a type-10 logon of `sf-test-user` to WS01. Rule 100501, level 12, for `sf-test-admin`. Rule 100502, level 12, for computer DC01. MITRE `T1021.001`.

A type-2 logon does not fire 100500. A machine account does not. Source `10.10.10.1` does not.

## Observed result

`NOT YET VALIDATED`.

## False positives

An administrator opens a real RDP session to WS01 or DC01. That is a real type-10 logon and this rule is meant to show it.

## Tuning

Do not match the word RDP in the message. Do not add type 7 or type 3 here. Type 3 is SF-011. If a second lab admin account is created, add that full name as its own anchored check after you have seen the lab event. Do not switch the account check to a substring.

## Investigation

1. Read `targetUserName`, `ipAddress`, `workstationName`, and `computer`.
2. Confirm the computer is WS01 or DC01, and that the source is a lab VM.
3. Confirm the account is `sf-test-*` and that you opened the session.
4. If the source is unexpected, keep the address and log the session off.

## Remediation

Log off the RDP session. Delete leftover `sf-test-*` accounts. Restore the snapshot if you are not sure what changed. This is a lab action, not an automated response.
