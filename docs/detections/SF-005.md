# SF-005 — Encoded PowerShell process

## Objective

Alert when Sysmon logs process creation for `powershell.exe` or `pwsh.exe` and the command line carries `-EncodedCommand`, `-enc`, or `-e` plus a base64 token. The technique on this alert is `T1059.001` only.

## ATT&CK

`T1059.001` PowerShell. Execution.

## Telemetry

Sysmon operational event 1 on WS01. The fields are `win.eventdata.image`, `win.eventdata.commandLine`, and `win.eventdata.parentImage`.

Chain: 60000 → 60004 (Sysmon channel) → 61600 (informational) → 61603 (event ID 1). File `0595-win-sysmon_rules.xml`. The content rules live in `0800-sysmon_id_1.xml` and use `(?i)` pcre2.

Security 4688 is not this rule. The only 4688 rule in this image is 67027 in `0955-WEF-baseline_rules.xml`. It is level 3, "A process was created," and it does not read `commandLine`. Command-line auditing for 4688 stays a lab check. It is not assumed here.

## Logic

One process creation is enough.

The image must end in `\powershell.exe` or `\pwsh.exe`. The command line must contain `-EncodedCommand`, `-enc`, or `-e`, then whitespace, then at least 8 characters from the base64 alphabet. `-e hi` does not qualify. `-Command` does not qualify.

Stock rule 92057 is level 12, MITRE `T1059.001`. It requires a `powershell.exe` parent and the word `powershell.exe` in the command line. Its flag expression uses a word boundary, so the common form `-enc` is not in that list as its own token. It does not mention `pwsh.exe`. This image has no `pwsh` rule at all.

Stock 92071 is also level 12 but only after WMI (92070), and it adds MITRE `T1047`.

Rule 100210 is level 13, still high (ADR 0004). It is one above 92057 so this description wins when both match. MITRE stays `T1059.001` only.

## Exclusions

- `commandLine`, `image`, or `parentImage` containing `ossec-agent` or `sentinelforge-setup`.
- Nothing else.

A PowerShell process whose parent image is the Wazuh agent is excluded. A setup script must put `sentinelforge-setup` on the command line.

## Validation procedure

Mac: `make logtest ID=SF-005` prints LIMITED.

Lab, Step 13, not run. **REQUIRES WINDOWS VALIDATION.**

1. Snapshot WS01 first.
2. On WS01 only, run an Atomic Red Team test for `T1059.001` that starts an encoded PowerShell process. Stay inside `sentinelforge.lab`.
3. Run that test's cleanup. End leftover `powershell.exe` and `pwsh.exe`. Restore the snapshot if the host changed.

The lab-reference token `U1lOVEhFVElD` is the word `SYNTHETIC`. It is not a payload.

## Expected result

Rule 100210, level 13, description starting with `SF-005`, MITRE `T1059.001` only.

`powershell.exe -e hi` does not fire it. `powershell.exe -Command Write-Output hello` does not. The same encoded command with parent `ossec-agent` does not.

## False positives

A software installer or management agent launches PowerShell with an encoded command. Those are real on a workstation. The Wazuh agent path is the exclusion above. Other management agents are not excluded.

## Tuning

Raise the base64 minimum above 8 if short tokens are noisy. Do not drop the token requirement, or every `-e` flag becomes an alert. Do not add `T1047`.

## Investigation

1. Read the image, command line, and parent image.
2. Confirm the host is WS01 and that you started the Atomic test.
3. If the parent is not yours, record the parent path and end the process.

## Remediation

End the process on WS01. Restore the snapshot if the command's effect is unclear.
