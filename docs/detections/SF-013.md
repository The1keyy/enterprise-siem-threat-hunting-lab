# SF-013 — Linux SSH failure burst

## Objective

Alert when one source IP produces six sshd authentication failures inside 120 seconds. This is password guessing (`T1110.001`) against UBU01.

## ATT&CK

`T1110.001` Password Guessing. Credential Access.

## Telemetry

- Program `sshd` in syslog.
- Logtest location used here: `/var/log/auth.log`.
- The line must contain `invalid user` (rule 5710, our 100701) or `Failed password` for a real account (rule 5760, our 100702).
- **VERIFY:** Ubuntu 24.04 may ship journald without `/var/log/auth.log`. The agent path is not confirmed until UBU01 is checked.

## Logic

Wazuh 4.14.9 already has brute-force rules 5712, 5720, and 5763. They wait for 8 matches and use MITRE `T1110`, not `T1110.001`.

SF-013 uses `frequency="6"` and `timeframe="120"` with `same_source_ip`, which those stock rules also use. Six is past a few typos and still shorter than the stock 8, so a lab burst shows up here before 5712 or 5763. Level 10 matches those stock rules and is medium under ADR 0004.

Logtest on this image: the 6th invalid-user line fired 100701. The 5th stayed 5710. The 6th known-user `Failed password` fired 100702. Alternating two source IPs did not add up.
