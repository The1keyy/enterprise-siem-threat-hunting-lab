# SF-006 — PowerShell download cradle

## Objective

Alert on a PowerShell download cradle in two places: the 4104 script text, and a Sysmon event 3 TCP connection from PowerShell when one is logged. The technique is `T1105`.

## ATT&CK

`T1105` Ingress Tool Transfer. Command and Control.

## Telemetry

Both of these, on WS01 for the planned simulation:

- PowerShell Script Block Logging, event 4104. Same parent chain as SF-004 (91802).
- Sysmon operational event 3. Chain 60000 → 60004 → 61600 → 61605. Fields in this image: `win.eventdata.image`, `win.eventdata.protocol`, `win.eventdata.destinationIp`, `win.eventdata.destinationPort`.

The two rules do not wait for each other. A script block with no connection still fires 100220. A connection with no script block still fires 100221. Joining them into one incident is later work.

## Logic

Rule 100220, level 12 (high), matches 4104 text containing `Net.WebClient`, `DownloadString`, `DownloadFile`, `Invoke-WebRequest`, or `Start-BitsTransfer`.

No rule under `/var/ossec/ruleset/rules` matches those five strings. Stock PowerShell rules do not cover this cradle.

Rule 100221, level 10 (medium), matches Sysmon event 3 when the image is `powershell.exe` or `pwsh.exe`, the protocol is `tcp`, and `destinationIp` is not `-`, `127.0.0.1`, `::1`, or `0:0:0:0:0:0:0:1`.

Stock 92101 is level 0, `powershell.exe` over TCP, MITRE `T1095`. It does not alert and it does not include `pwsh.exe`. 100221 is the alerting form of that idea, with `pwsh.exe` added and loopback removed. The library row is high because 100220 is the cradle. 100221 is the noisier companion.

Exclusions are anchored paths, not script text. Script text is chosen by whoever runs the script, so a marker inside the block would hide a real cradle. 100220 has no path field to anchor, so it has no exclusion. 100221 excludes only an image that is the Wazuh agent executable, which is a different path from `powershell.exe`.

## Boundary with SF-004

100220 does not match `IEX` or `Invoke-Expression`. A block that only contains those strings is SF-004. A block that contains both a cradle string and `Invoke-Expression` can fire both rules.

## Exclusions

- 100220: none. Same reason as SF-004. Accept lab noise; tune after a lab baseline.
- 100221: `image` equal to `C:\Program Files (x86)\ossec-agent\wazuh-agent.exe`, and the loopback addresses above.
- Nothing else. Script text is not an exclusion.

Sysmon event 3 rules in this image do not use `parentImage`. A connection whose parent process is the Wazuh agent is not excluded. The image check still requires `powershell.exe` or `pwsh.exe`, so the agent executable and a PowerShell image cannot be the same path. The anchor is there so a later edit cannot drop it. VERIFY the executable name the same way as SF-005.

## False positives

An administrator script uses `Invoke-WebRequest` for a lab file. Lab setup scripts that use the cradle strings also alert, because 100220 has no path exclusion. PowerShell opening any non-loopback TCP connection, including remoting and updates, fires 100221. That rule is level 10 on purpose.

## Tuning

If 100221 is noisy, limit `destinationPort` after you have seen real lab connections. Do not silence 100220 to quiet the network half. Do not add `IEX` to 100220. Do not exclude a word inside `scriptBlockText`.

## Investigation

1. Read the script text if the alert is 100220, or the image and destination if it is 100221.
2. Look for the other SF-006 rule in the same minute on WS01.
3. Confirm you started the Atomic test and that `10.10.10.200` is your lab source.
4. If the destination is unexpected, record it and end the process.

## Remediation

End the PowerShell process. Restore the WS01 snapshot if a file landed and you do not want to keep it.
