# SF-007 — User added to local Administrators

## Objective

Alert when Security 4732 adds a member to the local Administrators group. The group is identified by SID `S-1-5-32-544`, not by its display name. The technique is `T1098`.

## ATT&CK

`T1098` Account Manipulation. Persistence.

## Telemetry

Audit Security Group Management, Success. That policy writes 4732.

The planned simulation is on WS01 (`10.10.10.20`). The same event on DC01 is the domain built-in Administrators group and also matches. The rule does not filter the computer name.

Chain in this image: 60000 → 60001 (Security) → 60103 (audit success) → 60113 (group account changed) → 60144 (event 636 or 4732). File `0580-win-security_rules.xml`. Rule 100300 adds `^4732$` and `targetSid` `^S-1-5-32-544$`.

Fields used: `win.system.eventID`, `win.eventdata.targetSid`. `memberSid`, `memberName`, `subjectUserName`, and `targetDomainName` are present on the event and are not the match.

## Logic

One add is enough. This is not a frequency rule.

Stock 60154 is level 12, `if_sid` 60144 and 60145, the same SID, MITRE `T1484`. It also matches a removal (4733). Level 13 is high (ADR 0004) and is above 60154, so an add is labeled SF-007. A removal stays on 60154.

The match is the SID. A 4732 whose `targetUserName` says Administrators and whose `targetSid` is something else does not fire.

Exclusions use anchored SIDs, not a group name. This rule has no exclusion: every add to `S-1-5-32-544` is the behavior.

## Exclusions

None.

## Validation procedure

Mac: `make logtest ID=SF-007` prints LIMITED.

Lab simulation not run. **REQUIRES WINDOWS VALIDATION.**

1. Snapshot WS01 first. Snapshot DC01 too if you will touch the domain built-in Administrators group.
2. On WS01, inside `sentinelforge.lab`, run `scripts/powershell/simulations/SF-007-LocalAdmins.ps1`. It adds `sf-test-bob` to local Administrators. It does not download an Atomic test.
3. Run `SF-007-LocalAdmins-Cleanup.ps1` and confirm `sf-test-bob` is gone from Administrators. Restore the snapshot if the host changed.

## Expected result

Rule 100300, level 13, description starting with `SF-007`, MITRE `T1098`.

A 4732 for `S-1-5-32-545` does not fire it. A 4733 removal from `S-1-5-32-544` does not. A display name of Administrators with SID `S-1-5-32-545` does not.

## Observed result

`NOT YET VALIDATED`.

## False positives

An administrator adds a lab account to local Administrators on WS01. That is a real 4732 and this rule is meant to show it.

## Tuning

Do not match the group name. Do not add 4733. If WS01 service accounts are added to Administrators on purpose, exclude that member by its full SID after you have seen the lab event.

## Investigation

1. Read `targetSid`, `memberSid`, `memberName`, and `subjectUserName`.
2. Confirm the computer is WS01, or DC01 if you changed the domain built-in group.
3. Confirm the account is `sf-test-*` and that you started the Atomic test.
4. If the member is unexpected, keep the SID and remove the membership.

## Remediation

Remove the member from Administrators. Delete leftover `sf-test-*` accounts. Restore the snapshot if you are not sure what changed. This is a lab action, not an automated response.
